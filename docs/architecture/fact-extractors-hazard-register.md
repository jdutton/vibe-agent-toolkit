# Fact Extractors — Hazard Register

The living register of hazards the fact store enforces or accepts, under
[Fact Extractors](./fact-extractors.md) P1: no wrong answer at exit 0 from any hazard listed here.

Each row has a status — `enforced`, or `accepted` (`accepted, counted` where the cost is counted) —
and either the kind of enforcer that proves it red or the bound that limits it. A change that builds
part of the design adds or updates its rows in the same PR. A new hazard becomes a row here, never a
new rule in the ADR. Rows name invariants and mechanisms, never plan steps.

A status is the design's commitment for that hazard. Like the ADR it serves, the register is decided
and not yet built: an `enforced` row holds only once the change that builds its enforcer has proved
it red on a seeded violation.

|---|---|---|

| Undetected plugin impurity | accepted | Bound: refused at load (`EXTRACTOR_UNCONFORMED`, naming `vat extractor test`) until a pass is recorded outside the evictable store under the plugin's source closure plus the compatibility digest, no runtime tuple (I2's exemption; sampling covers a new runtime). Rejected: running it unconformed. |
| Plugin trust | accepted | A plugin has the user's rights and writes any project's facts; the store copies what it reads (value and line extractors opt in); PR CI runs the author's code. Bound: CI caches are ref-scoped, never restored from a PR into a protected branch; its rows leave only by eviction or `vat cache clear`. |
| Non-module code payloads (wasm, data files) | enforced | Files read while a module evaluates join its code identity; the observed-inputs instrument. |
| git's env, config and global file inputs | enforced | Membership: the extent key is git's tree hash; I0 seed `globalExcludes`. Every call through `runGit` but the ambient `git --version` scrubs the redirect env and sets the pathspec env to `0`; a real-git test with `GIT_ICASE_PATHSPECS=1` exported. |
| git's redirect and pathspec env in the spawns vibe-validate's tree snapshot makes | accepted, requested of vibe-validate | Bound: those spawns take no env from `runGit`, so an exported `GIT_DIR`/`GIT_INDEX_FILE` (a worktree's git hook) or `GIT_*_PATHSPECS` can reach at most the snapshot that keys the extent; every other git call VAT makes is scrubbed and overridden. Closed when vibe-validate scrubs or overrides them in its own spawns. |
| Normalization beneath an unchanged tree hash (`text`/`eol`, `core.autocrlf`, a clean/smudge filter) | accepted until the stat memo lands | Bound: the bytes on disk move while git's cleaned blob does not, so a warm hit serves the previous bytes' facts; documented by the I0 seeds `autocrlfFlip`, `cleanSmudge`, `globalAttributesEol`; closed by the stat memo. |

| A repo another user owns | accepted, no seed | Bound: git's own dubious-ownership check decides, and VAT reports it only as git not answering; the control is git's `safe.directory` in the operator's config; VAT adds none. Rejected: the non-git lane (silent). |
| git's repo-local file inputs and binary | enforced | Declared extent-key inputs; a Linux-only file-open trace following children (`-f`), both ways, covering {index, objects, refs, packs}. A filter driver's effect on bytes is the normalization row. |

| Identifier case collision | enforced | Relation naming (settled); refused at config load; manifest columns, which SQLite matches case-insensitively, by the static manifest check. |
| PID reuse | enforced | Liveness is PID plus process start time; a two-process test. |
| Lease start time | enforced | The kernel's stored process creation time, one source on writer and checker sides (Linux: `/proc`); doubt means alive; two-process test, clock seam stepped. |
| Cost: start-time probe off Linux | accepted, counted | A child process, killed at limit (I8). |
| Store across hosts or containers | enforced | A lease records machine id, boot id and PID namespace: same machine, boot and PID namespace: judged by PID and start time; same machine, other boot: dead; otherwise (another machine or PID namespace) foreign, so alive, never evicted; each seeded. |
| Store on a network filesystem | enforced on Linux; accepted on macOS, Windows | Linux: a store root whose fs type is not on an allowlist of known-local types refuses, naming the path; an unlisted type seeded. Elsewhere, bound: documented unsupported; a probe is Deferred. |
| Store shared with another OS user | enforced on POSIX; accepted on Windows | POSIX: a root not the current uid's, or group- or world-writable, refuses at every open, naming the path; seeded both ways. Windows bound: the root sits under the user's profile, per-user by default. |
| Module resolution drift | enforced | Code identity adds the specifier→file map, `NODE_PATH`, `--conditions`, re-resolved warm; a native addon hashes with its libraries or refuses; a shadowing file or `exports` edit misses. |
| Cost: code-identity validation | accepted, counted | One stat per closure file plus re-resolution, memoised under the stat memo's racy rule. |
| ctime not independent of mtime | enforced | A first-use probe per filesystem; if ctime stays with mtime held, the stat memo is distrusted there, bytes re-hashed (counted); a stat-seam fixture. |
| A plugin loaded through an import wrapper | enforced | I11's lint and allowlist. |
| A plugin hangs at module evaluation | enforced | Kill at limit (I8). |

| Eviction or retirement mid-run | enforced | Leases (settled); I7's test. |
| Crash mid-write | enforced | I6's kill mid-write. |
| Claim held under a lease judged alive | accepted, counted | Bound: a waiter at its limit extracts the pair itself, idempotently. |
| Schema introspection sees the hydration set | enforced | One lane on every runtime until the declared floor has an authorizer: `EXPLAIN` at prepare, counted, refuses an `OpenRead` of root page 1 (the schema table) and any virtual-table open but `json_each`/`json_tree`, by identity (virtual-table pointer equal to theirs on the connection), never name or alias; bare `PRAGMA` and second statements, the store's keyword and single-statement guard. | Answer depends on hydration order | enforced | Hydration inserts rows in canonical order (path, then row ordinal); I0 seeds an order-dependent statement. |

| Absence read as empty | enforced | I1's enforcer. |
| Spurious refusal | enforced | I0's differential: zero refusals, unseeded corpus, every arm, limits outside the measured range; limit refusals counted apart. |
| Stale key from another history | enforced | I0's warm arm on a store another history populated. |
| Core-producer and resolve memo inputs | enforced | Each input moved alone misses (I2). |
| Federated or core relations without `root` | accepted until relations carry `root` | Bound: in a multi-root run a statement over one refuses; a two-root seed. |
| Store growth from unreadable or foreign leases | accepted, counted | Bound: a same-machine lease from another boot is dead, so evictable; a pinned-bytes counter; a warning names `vat cache clear`. |
| Cost: stats, one per population file plus a fixed few | accepted, counted | Per file, never per byte; the pre-answer re-stat included. |
| Cost: full extent derivation | accepted, counted | Gated once the incremental extent lands. |

| Cost: lens evaluation decodes rows | accepted, counted | Gated once its core producer lands. |
| Cost: racy re-hash | accepted, counted | Bound: racy-granule entries re-hash every run; memo refreshed after the answer. |
| Cost: any edit to the contract closure refuses every plugin | accepted | Bound: a minimal closure, runtime imports confined (settled). |

| A pathological document hangs, exhausts the heap or overflows the stack in the parser | enforced for every parse and frontmatter decode; `vat rag index` parses nothing | One bounded worker per job (I8). Time and heap breaches kill and replace the worker, each proved by Node's thread table returning to its baseline; stack and output breaches are reported by it; input size is refused before dispatch, by one comparison (`inputBytesBreach`) in one unit, the bytes the content came from: every read made for a parse is refused by its `fstat` size before a byte is read (`readContentWithKey`, its cap a required argument, reached for a route through `readContentForParse`), and hands on that size with the text (`MeasuredContent`), so no lane re-measures it; a ZIP entry is held by its declared size (`parseInputRefusal`) and measured in its own bytes once inflated; accepted, re-reads that hand nothing to a parser are not held to the cap — the compat detectors' re-read of a linked file the skill validator already parsed under the cap, its implicit-reference scan, the packager's read-back of a packaged markdown file for its links, and the compatibility analyzer's Python import scan; content never read is measured as its UTF-8 bytes (`inMemoryContent`) — seeded one byte past a cap on each `SKILL.md` lane in `skill-md-input-cap.integration.test.ts` (agent-skills) and `skill-md-input-cap.test.ts` (claude-marketplace, which also reads a UTF-16 `SKILL.md` under the cap in its own bytes and past it as UTF-8 on every lane); a cache hit is held to the dispatcher's own output caps (`parse-dispatcher-bounded.test.ts`); the read lane's boundary — exactly the cap admitted, one byte more refused, as the pool's `>` — in `oversize-content.integration.test.ts`), so a 3 GiB file is the input cap's refusal, never a read failure, and the projection's `oversize` realization of a parsed kind is the same `RESOURCE_PARSE_LIMIT_EXCEEDED` the registry reports (`oversize-content.integration.test.ts`; `vat resources validate` and `check` agree on a sparse oversize `.md`, `population-refusal-report.system.test.ts`). Each limit has a breach fixture. Frontmatter YAML is decoded only in the worker, and an overflow there (a `YAMLParseError` wrapping a `RangeError`) is a `stackMb` breach, never a `frontmatterError`; the depth seed names its `stackMb` (1 MiB) and nests 20,000 levels. Frontmatter counts against `outputRows` and `outputBytes` as exactly the JSON the store writes for it (`expandedSize`): every array element and every mapping entry a row, its bytes those of its `JSON.stringify`, each alias at its target's full size, a `!!binary` as its `Buffer` JSON (one row per byte, each byte its digits), a `!!set` as the list of its members and a `!!omap` as the mapping of its entries, as the codec carries them across the wire (rows, bytes, depth and cycles alike) — never over the encoding that crosses the wire, which writes a shared anchor once, nor over a binary's base64. Seeded with an anchor aliased 99 times, refused, nothing stored; with a 3.9 MB `!!binary` (11.8 MB of stored JSON, 2,945,731 rows), refused at `outputRows`; with eight value shapes whose rows and bytes must equal their stored JSON's exactly; and with a 1,000,000-member `!!set` and a 1,000,000-entry `!!omap` (refused at `outputRows`), 3,000 levels nested inside a `!!set` (refused at `outputDepth`) and a set that contains itself (refused, depth infinite) (`parse-limits.test.ts`), plus a 2,000-member `!!set` and a 2,000-entry `!!omap` refused through the pool (`parse-pool-limits.integration.test.ts`). Frontmatter also counts against `outputDepth`, its depth as JSON (default 1,000, and `resolveParseLimits` refuses any value past 1,000 — SQLite's JSON depth, past which one stored row makes every `json_extract` over the column throw); a cyclic anchor nests without end and is the same breach, never a value a JSON writer meets. The refusal names the depth found. Seeded at 1,000 and 2,000 nested lists (1,001 and 2,001 levels) and at `a: &x [*x]`: each refused, nothing stored, and a `json_extract` over the remaining rows still answers (`population-refusal-report.system.test.ts`). `vat rag index` chunks by the registry's facts and reads only text (`lancedb-rag-provider.ts` `indexResource`). The run refuses the file, naming it and the limit, and keeps every other file's rows. Nothing persists (I6). |
| The parse worker dies holding a job (it exits, or an uncaught error kills it) | enforced | The job rejects with `ParseWorkerDiedError`: a per-run `BLOB_PARSE_WORKER_DIED` on the projection lane, `RESOURCE_PARSE_WORKER_DIED` on the registry lane, never `BLOB_PARSE_FAILED`, never stored (I6). Seeded with a worker that calls `process.exit(1)`: the file is refused, nothing is stored, and the next run re-attempts it. Only a throw the worker brands as the parser's own, raised from the document's bytes (`fromDocument`, revived as `ParserThrewError`), may become the stored `BLOB_PARSE_FAILED`; every other error reaching `parseTarget` is rethrown, so a revived infrastructure error is never filed against a document (`projection-blob-parse-failure-attribution.test.ts`, `parse-pool.test.ts`). |
| A broken install reported as a worker death of each document in turn | enforced | A worker posts `ready` once its module graph has loaded. A thread that dies before it, or three threads in a row dying with no answer between them, or three counted load-clock stops of one parser kind with that parser loaded nowhere between them (`timeMs` without their job's parser loaded, which the worker announces once per kind before that parser runs; see the slow-start row), is a broken install, and so is a worker entry that does not resolve or a `Worker` that will not construct: every held, queued and later job fails with a `ParserUnavailableError`, which every lane rethrows (the run fails loud, nothing is blamed on a document, nothing is stored): a per-file catch classifies what it caught through one allowlist, `classifyParseFailure` (a per-run refusal, the parser's own throw over the bytes, a read the OS refused), which rethrows everything else, this included; held by `parse-failure-classifier.test.ts` (dev-tools), which refuses a bare `isParserUnavailable(` guard in any `src` file (proved red by reintroducing one), and seeded on the inventory lane with a partly warm skill whose link walk meets a broken install (`extract-skill-broken-install.test.ts`: rejects, where it filed a `link walk failed` row `vat audit` dropped at exit 0). Seeded with a built package copied without `parse-worker.js` — the pool's real existence check, no test seam — which fails parser-unavailable, files no `blob_conditions` row, and parses normally once the file is back (`missing-parse-worker.integration.test.ts`); with a worker entry that throws as its module loads, one that loads and dies on every job, and one that starts and never loads a parser (one document stopped at its load clock three times, then parser-unavailable); an answer between deaths resets the count, an idle thread's death (one holding no job after `ready`) never counts (three idle deaths, then a document admitted), and a time breach after the parser loaded is a slow document, never counted: three pathological documents stopped at once on three fresh threads stay three `timeMs` refusals (the width seed below). The deadline decides only after the messages already queued on the port settle (it re-checks in `setImmediate`), so an answer or a `parserLoaded` that arrived first wins; and a stop the parent itself made late (fired more than one heap-sample interval, 50 ms, after it was due) neither counts toward the three nor resets them, since a parent that late may have starved the thread it judges. Seeded with a parent that busy-waits past `timeMs` while a fast document is in flight (admitted, breaker untripped) and with one document whose three threads are each stopped late (that one job ends as a `ParserUnavailableError` saying its parser could not start within `timeMs` on three threads in a row; the breaker is not tripped); the load-clock seed runs on fake timers driven by a ready marker, never on wall-clock races (`parse-pool.test.ts`). An answer is credited only to the job it names: a reply whose `id` is not the held job's, or one from a thread already retired, is ignored, so it neither settles a job nor resets the count (a retired thread's `parserLoaded` is never an answer; it counts only as evidence that the parser loads, which ends a run of load-clock stops for it) (seeded with threads that each post a stale id and then die: two deaths, then parser-unavailable, `parse-pool.test.ts`). |
| A parse pool runs wider than its size while breached threads exit | enforced | A thread terminated at a time or heap limit, or one that died uncontrolled and is still exiting, counts against `size` until its `exit`; only then is its replacement spawned, and shutdown awaits it. Shutdown never rejects and never changes a run's result: a thread whose close fails (an `error` while closing, or a park whose heap read throws) is terminated like any other, every thread is gone when it settles (seeded with threads that throw on shutdown: it resolves and the thread table returns to its baseline, `parse-pool.test.ts`). Seeded by breaching every thread of a pool at once with jobs queued behind: the live threads, counted from each `Worker`'s construction to its `exit` (`diagnostics_channel` `worker_threads`), never exceed `size`; and with a thread whose `exit` lags the `error` it died of by 400 ms, a pool of one never runs two. |
| A parked parse thread keeps a command alive, ends it early, or carries one run's failure into the next | enforced | A pool's shutdown parks a thread only if it loaded, holds no job, is still alive, and holds at most `PARKED_HEAP_MB` (48 MiB) of used heap, twice what a fresh thread holds after loading both parsers (`#park` in `parse-pool.ts`), so a large crawl's leftover is never held idle; what a parked thread carries into the next pool is bounded by that pool's reuse check like any reused thread's (at most B, an eighth of the applied bound, past a fresh thread, the heap-flag row), at every applied bound, so a lowered bound declines none. No thread is parked from a pool judged a broken install, or from a run recording parse timing. A parked thread is `unref`'d, is adopted only by a pool whose `workerKey` (entry, `workerData` with its limits, `execArgv`, environment) is equal, starts each job under that pool's limits, is checked at its first job like any reused thread (collected past `reusedThreadHeapMb`, and retired to a fresh thread if still past it, the heap-flag row), and is dropped without counting as a death if it dies while parked; one that dies after it was adopted and before its heap check for its job reaches the pool is charged to no document, and its job runs again on a fresh thread, as for any reused thread (the slow-start row). The shutdown's heap read re-`ref`s the thread first: from an unref'd thread it held nothing open, and a real process exited mid-shutdown at code 0 (seeded in a child process, `parked-parse-worker-exit.integration.test.ts`; park, adopt, eviction and every refusal in `parse-pool.test.ts`). Cost: idle threads stay parked beside a live pool, each under 48 MiB of used heap, at most `defaultParsePoolSize()` and at most what memory leaves (next row), and each closes itself after `PARKED_IDLE_MS` (5 s) unadopted, on an `unref`'d timer that adoption cancels, so a long-lived host gets the memory back with nothing to call. |
| A parse pool's worker heaps together exceed the machine's memory | enforced | Bound: `size × workerHeapCeilingMb(heapMb)` (twice `heapMb`) ≤ `min(process.constrainedMemory(), os.totalmem())` − 1,024 MiB reserved for the main thread. The width is lowered first; if not even one worker fits, the pool runs one worker at the largest heap that fits, floored at 96 MiB. `VAT_PARSE_POOL_SIZE` and an explicit `size` are capped by the same bound (`memoryBoundedPool`, `parse-limits.test.ts`; the pool applies it in `createParsePool`, `parse-pool.test.ts`). Threads parked between pools are charged their whole `heapMb` each against what that bound leaves beside a pool as wide as the parking pool's own width or `defaultParsePoolSize()`, whichever is wider, and a pool parks none where nothing is left. A wider pool pinned elsewhere in the same process (a `VAT_PARSE_POOL_SIZE` or policy `size` above both) is not counted, so beside one the parked threads can exceed that bound by their charge (`parkedThreadRoom`, `parse-limits.test.ts`; the pool applies it as its park cap, `parse-pool.test.ts`). |
| The parent cannot rebuild a worker's answer, or a stored entry's frontmatter | enforced | The frontmatter codec is loops on every encode and decode path (no spread, `apply`, `flatMap` or recursion), so no size or depth of input reaches a throw: a 2,000,000-element list round-trips. The worker emits only what the decode accepts: a frontmatter root is admitted only when it is a plain mapping (`isPlainMapping`, prototype `Object.prototype` or `null`, in `frontmatter-codec.ts`), and a `!!set`, `!!omap`, `!!timestamp` or `!!binary` root is `frontmatterNotAMapping` like a sequence — seeded with each, cold and warm, no crash. The skill lane's frontmatter (`parseFrontmatter` in `agent-skills`) is the worker's decode — it hands the block to the bounded route and reads back `frontmatter`, `frontmatterNotAMapping` and `frontmatterError` — keeping only the delimiter scan and the empty rule (a block that declares nothing is no frontmatter, never a non-mapping), so both lanes give one answer per block, a cyclic, a 1,001-deep and a typed root included — seeded with the four typed roots, a sequence, a scalar, four empty shapes, a cyclic anchor and a 1,001-level block on both (`frontmatter-lane-agreement.integration.test.ts`); `encodeFrontmatterValue` refuses any other root rather than writing one the decode would reject. Seeded through a decode made to throw on each lane, and through a stored entry rewritten to a non-JSON encoding. |
| Cost: key-determined parse-limit breaches (output and input caps) re-attempted every run | accepted, counted | Bound: the caps are functions of the bytes, so the same file breaches the same output cap every run and is parsed again each time; each breach is counted and named per run. The input cap is decided by the file's size before it is read, so it costs a `stat`, and on the projection lane it is an `oversize` row the store holds under a key that names the cap, never a per-run store miss (`projection-store-roundtrip.test.ts`). | A process-wide heap flag (`--max-old-space-size` in `NODE_OPTIONS` or `execArgv`) lifts or lowers a worker's `resourceLimits`; a worker reaching V8's own ceiling kills the whole process | enforced; the parent-stall window accepted, bounded | The pool, never V8, enforces `heapMb`: it samples each worker's whole used heap every 50 ms, which never understates the old generation, and declares a breach by `heapBreached`: a reading past the applied bound counts only once it fell from the same job's previous reading by more than the young generation (read from the worker's `resourceLimits`; on Node 26.7, 192 or 96 MiB by host — more than a scavenge can free, so an old-generation collection ran and what is left is held), and a heap that keeps rising with no such fall is stopped once its whole used heap passes `stopMb` (halfway from the bound to V8's ceiling: 1,536 MiB at the defaults, 768 under a 1,024 MiB flag, 384 under 512). Every job, on any thread, is judged against that one bound and stop. A reused thread is held to start its job near what a fresh one holds: before the job it reads its own heap, and past `reusedThreadHeapMb(appliedMb)` (a fresh thread's `FRESH_THREAD_HEAP_MB`, 24 MiB — measured 23.3–24.1 once both parsers have loaded — plus B = ⌊appliedMb / 8⌋: 152 MiB at the defaults, 88 under a 1,024 MiB flag, 56 under 512) it forces a full collection of its own heap and reads again; still past, it is retired before it runs anything, and the job runs on a FRESH thread, never another reused or parked one, a thread start that counts toward nothing, while the jobs behind it may use an idle thread (`settleReusedHeap`; the pool samples a reused thread only once its check has reported). Seeded: the same stop on a reused thread as on a fresh one and no sample before the check; garbage past the bound collected by a real full collection and the thread kept; exactly the bound kept with no collection; one byte past it after a collection retired, the job on a fresh thread; an adopted parked thread checked as reused; the jobs behind a retired one served meanwhile (`parse-limits.test.ts`, `parse-pool.test.ts` "a heap past its bound"). So the stall margin is the same on a reused thread as on a fresh one, short by at most B, an eighth of the bound: the worst-case difference between a job's verdict on a fresh and on a reused thread. The collector is V8's `gc`, taken once as the worker loads (`acquireCollector`, `parse-collector.ts`): under one lock per copy of the library — an `Int32` in a `SharedArrayBuffer` the pool hands every thread, taken from a holder that keeps it past 2 s — the thread sets `--expose-gc`, creates one context to take its `gc`, and clears the flag, so no context the host creates afterwards has a `gc` and `v8.cachedDataVersionTag()` is as it was (seeded in a child process after a pool ran; 16 threads × 5 rounds on one lock all had one; a stale holder's lock taken and freed, `parse-collector.integration.test.ts`). Unlocked, clearing raced: Node 24.21 and 26.7, 29–36 of 400 threads started 8 at once and 94–95 of 800 at 16 had none; under the lock, 0 of 400 and 0 of 800. A process run with `--expose-gc` has one on the thread's global, which is used, and the flag is never touched. **Residual, accepted:** two copies of the library in one process hold two locks and can still race, and so can a host that sets or clears the flag itself; a context another thread creates while the flag is held gets a `gc` too; and a holder terminated between setting the flag and clearing it leaves `--expose-gc` set, process-wide, until the next thread acquires. The cost of a lost race is a thread with no collector. With none — a runtime that refuses the flag included, which is caught rather than failing the thread's load — the worker says so in its `ready`, the process is warned once (`VAT_PARSE_NO_COLLECTOR`), and a reused thread past the reused-thread bound is retired rather than collected, its job on a fresh thread: a thread start, never a verdict decided by what earlier jobs left (seeded: `v8.setFlagsFromString` throwing, the thread past the bound retired, its job answered on a fresh thread, one warning). Measured with the lab's `reuse-check` / `reuse-collect` / `reuse-retire` tier passes (`fact-extractors-limits.md`, "A reused thread", formula and table): B was picked from them, as the share that keeps the check under 2% of worker time at every flag — a fixed 8 MiB collected before a quarter of the jobs (7.7–10%), a sixteenth before 12% under a 512 MiB flag (4.75%); at an eighth, 0.4–1.1% of checks collect and the check costs 0.21–0.63% of worker time, with 0 threads retired, over 390 checks on VAT's tree (1,024 and 512 MiB flags) and 3,175 on an adopter's 2,680 documents (1,024 and 768). For example, under a 1,024 MiB flag (applied 512, B = 64, bound 88 MiB) the heaviest reused thread started its job at 87.5 MiB, 63.5 MiB past a fresh one. Garbage V8 has not collected is never a breach: a 10,000-level blockquote (live heap about 420 MiB, used heap 1,031–1,157 MiB on a loaded host with no collection) was refused in 3 of 10 cold runs under 8 busy loops and is admitted 28 of 28 (`population-refusal-report.system.test.ts`, every skill verb and `resources validate`; `parse-limits.test.ts`, `parse-pool.test.ts` "a heap past its bound"). V8's ceiling sits at twice `heapMb` (`workerHeapCeilingMb`), because a worker that reaches it dies with a FATAL out-of-memory: when the ceiling was `heapMb` itself (64 MiB), a worker under fast allocation reached it before the sampler could stop it, and the FATAL took the process down in 3 runs of 4 on Node 26. A configured `heapMb` is at least 64 MiB (`MIN_HEAP_MB`), the bound seeded clean: three no-flag breaches in a row at 64, each in a child process that exits 0; a smaller one is refused because it was not seeded clean — on Windows CI the vitest fork running a pool at 32 exited unexpectedly twice, with no exit reason captured, while a breach stopped at an applied 32 MiB bound under a 64 MiB flag runs cleanly in a child, so 64 is the least bound seeded, not a measured safety threshold.
