# Fact Extractors — Hazard Register

The living register of hazards the fact store enforces or accepts, under
[Fact Extractors](./fact-extractors.md) P1: no wrong answer at exit 0 from any hazard listed here.

Each row has a status — `enforced`, or `accepted` (`accepted, counted` where the cost is counted) —
and either the kind of enforcer that proves it red or the bound that limits it. A change that builds
part of the design adds or updates its rows in the same PR. A new hazard becomes a row here, never a
new rule in the ADR. Rows name invariants and mechanisms, never plan steps.

A status is the design's commitment for that hazard. Like the ADR it serves, the register is decided
and not yet built: an `enforced` row holds only once the change that builds its enforcer has proved
it red on a seeded violation.

| Hazard | Status | Enforcer kind, or bound |
|---|---|---|
| Clock regression | accepted | Bound: a stale hit needs a backward step within one granule, size, ino and ctime unchanged; `--verify` or a cold run clears it. |
| Undetected plugin impurity | accepted | Bound: refused at load (`EXTRACTOR_UNCONFORMED`, naming `vat extractor test`) until a pass is recorded outside the evictable store under the plugin's source closure plus the compatibility digest, no runtime tuple (I2's exemption; sampling covers a new runtime). Rejected: running it unconformed. |
| Plugin trust | accepted | A plugin has the user's rights and writes any project's facts; the store copies what it reads (value and line extractors opt in); PR CI runs the author's code. Bound: CI caches are ref-scoped, never restored from a PR into a protected branch; its rows leave only by eviction or `vat cache clear`. |
| Non-module code payloads (wasm, data files) | enforced | Files read while a module evaluates join its code identity; the observed-inputs instrument. |
| git's env, config and global file inputs | enforced | Pinned (settled); env, config and pass-through allowlists, both ways. |
| Behaviour-defining config dropped by pinning | enforced | Once per effective-config hash (counted), the extent's file list and status are compared, pinned vs unpinned git; a difference refuses, naming it, unless the key is dropped deliberately (`core.excludesFile`); Windows CI with system `autocrlf=true`, and an LFS-filter fixture: an unchanged tree has zero changed files. |
| git older than the pinning floor | enforced | Refuses, naming the version found and the floor, the lowest version honouring every pinning variable; a stubbed `git --version` seed. |
| An index bit (assume-unchanged / skip-worktree) hides a change | enforced | Refuses, naming the path, except a skip-worktree file absent in a sparse checkout; each bit seeded. |
| Cost: pinned git drops performance keys (`core.fsmonitor`, `core.untrackedCache`, `feature.manyFiles`) | accepted, counted | The answer is unaffected because the keys are dropped. |
| A repo another user owns | enforced | Refuses, naming git's dubious-ownership cause and its control (settled): exact paths, `*` refused, an extent-key input (I9). Rejected: honouring global config (un-pins git); the non-git lane (silent). |
| git's repo-local file inputs and binary | enforced | Declared extent-key inputs, with each passed-through `filter.<driver>` command's resolved binary and version; a Linux-only file-open trace following children (`-f`), both ways, covering {index, objects, refs, packs} and the pass-through set; elsewhere, that plus the pinned env. An artifact derived through a passed-through filter driver is uncacheable, counted, unless the driver is allowlisted with its full input set proved by the trace fixture (LFS). |
| Coarse mtime granularity; a stat memo on another filesystem | enforced | I2a's racy rule, judged on the tree's own filesystem; a stat-seam re-hash test. |
| Identifier case collision | enforced | Relation naming (settled); refused at config load; manifest columns, which SQLite matches case-insensitively, by the static manifest check. |
| PID reuse | enforced | Liveness is PID plus process start time; a two-process test. |
| Lease start time | enforced | The kernel's stored process creation time, one source on writer and checker sides (Linux: `/proc`); doubt means alive; two-process test, clock seam stepped. |
| Cost: start-time probe off Linux | accepted, counted | A child process, killed at limit (I8). |
| Store across hosts or containers | enforced | A lease records machine id, boot id and PID namespace: same machine, boot and PID namespace: judged by PID and start time; same machine, other boot: dead; otherwise (another machine or PID namespace) foreign, so alive, never evicted; each seeded. |
| Store on a network filesystem | enforced on Linux; accepted on macOS, Windows | Linux: a store root whose fs type is not on an allowlist of known-local types refuses, naming the path; an unlisted type seeded. Elsewhere, bound: documented unsupported; a probe is Deferred. |
| Store shared with another OS user | enforced on POSIX; accepted on Windows | POSIX: a root not the current uid's, or group- or world-writable, refuses at every open, naming the path; seeded both ways. Windows bound: the root sits under the user's profile, per-user by default. |
| Module resolution drift | enforced | Code identity adds the specifier→file map, `NODE_PATH`, `--conditions`, re-resolved warm; a native addon hashes with its libraries or refuses; a shadowing file or `exports` edit misses. |
| Cost: code-identity validation | accepted, counted | One stat per closure file plus re-resolution, memoised under the stat memo's racy rule. |
| ctime not independent of mtime | enforced | A first-use probe per filesystem; if ctime stays with mtime held, the stat memo is distrusted there, bytes re-hashed (counted); a stat-seam fixture. |
| A plugin loaded through an import wrapper | enforced | I11's lint and allowlist. |
| A plugin hangs at module evaluation | enforced | Kill at limit (I8). |
| Mixed VAT builds on one store | enforced | The namespace (settled); I7's test. |
| Concurrent writer | enforced | Whole row sets (I6); I7's test. |
| Eviction or retirement mid-run | enforced | Leases (settled); I7's test. |
| Crash mid-write | enforced | I6's kill mid-write. |
| Claim held under a lease judged alive | accepted, counted | Bound: a waiter at its limit extracts the pair itself, idempotently. |
| Schema introspection sees the hydration set | enforced | One lane on every runtime until the declared floor has an authorizer: `EXPLAIN` at prepare, counted, refuses an `OpenRead` of root page 1 (the schema table) and any virtual-table open but `json_each`/`json_tree`, by identity (virtual-table pointer equal to theirs on the connection), never name or alias; bare `PRAGMA` and second statements, the store's keyword and single-statement guard. Seeds `dbstat`, `pragma_table_info`, `sqlite_schema`, `dbstat AS json_each`, `pragma_table_info(...) AS json_tree`, each alone and beside another statement. |
| Answer depends on hydration order | enforced | Hydration inserts rows in canonical order (path, then row ordinal); I0 seeds an order-dependent statement. |
| Tree mutated mid-run | enforced | Before the answer the extent is re-statted under I2a's racy rule, own-granule entries re-hashed (counted), and HEAD and the index re-read; any move refuses (tree moved); a two-process test checks out between extent derivation and answer; a stat-seam seed. |
| Ambient process inputs (`LANG`/locale, `TZ`, cwd, env) | enforced | Unseen by an fs-read instrument: the conformance suite runs every producer under two values of each, rows identical. |
| Absence read as empty | enforced | I1's enforcer. |
| Spurious refusal | enforced | I0's differential: zero refusals, unseeded corpus, every arm, limits outside the measured range; limit refusals counted apart. |
| Stale key from another history | enforced | I0's warm arm on a store another history populated. |
| Core-producer and resolve memo inputs | enforced | Each input moved alone misses (I2). |
| Federated or core relations without `root` | accepted until relations carry `root` | Bound: in a multi-root run a statement over one refuses; a two-root seed. |
| Store growth from unreadable or foreign leases | accepted, counted | Bound: a same-machine lease from another boot is dead, so evictable; a pinned-bytes counter; a warning names `vat cache clear`. |
| Cost: stats, one per population file plus a fixed few | accepted, counted | Per file, never per byte; the pre-answer re-stat included. |
| Cost: full extent derivation | accepted, counted | Gated once the incremental extent lands. |
| Cost: whole-relation hydration | accepted, counted; gated if push-down lands | Rows stay within the bound extent. |
| Cost: lens evaluation decodes rows | accepted, counted | Gated once its core producer lands. |
| Cost: racy re-hash | accepted, counted | Bound: racy-granule entries re-hash every run; memo refreshed after the answer. |
| Cost: any edit to the contract closure refuses every plugin | accepted | Bound: a minimal closure, runtime imports confined (settled). |
| Cost: re-attempts (per-run failures; failures stored under a tighter limit) | accepted, counted | The refusal names the file. Rejected: persisting a per-run outcome (I6). |
| A pathological document hangs, exhausts the heap or overflows the stack in the parser | enforced for the crawl lanes' parse and frontmatter decode; `vat rag index` parses nothing | One bounded worker per job (I8). Time and heap breaches kill and replace the worker, each proved by Node's thread table returning to its baseline; stack and output breaches are reported by it; input size is refused before dispatch. Each limit has a breach fixture. Frontmatter YAML is decoded only in the worker, and an overflow there (a `YAMLParseError` wrapping a `RangeError`) is a `stackMb` breach, never a `frontmatterError`; the depth seed names its `stackMb` (1 MiB) and nests 20,000 levels. Frontmatter counts against `outputRows` and `outputBytes` as exactly the JSON the store writes for it (`expandedSize`): every array element and every mapping entry a row, its bytes those of its `JSON.stringify`, each alias at its target's full size, a `!!binary` as its `Buffer` JSON (one row per byte, each byte its digits) and a `!!set` / `!!omap` as the `{}` JSON writes — never over the encoding that crosses the wire, which writes a shared anchor once, nor over a binary's base64. Seeded with an anchor aliased 99 times, refused, nothing stored; with a 3.9 MB `!!binary` (11.8 MB of stored JSON, 2,945,731 rows), refused at `outputRows`; and with eight value shapes whose rows and bytes must equal their stored JSON's exactly (`parse-limits.test.ts`). Frontmatter also counts against `outputDepth`, its depth as JSON (default 1,000, and `resolveParseLimits` refuses any value past 1,000 — SQLite's JSON depth, past which one stored row makes every `json_extract` over the column throw); a cyclic anchor nests without end and is the same breach, never a value a JSON writer meets. The refusal names the depth found. Seeded at 1,000 and 2,000 nested lists (1,001 and 2,001 levels) and at `a: &x [*x]`: each refused, nothing stored, and a `json_extract` over the remaining rows still answers (`population-refusal-report.system.test.ts`). `vat rag index` chunks by the registry's facts and reads only text (`lancedb-rag-provider.ts` `indexResource`). The run refuses the file, naming it and the limit, and keeps every other file's rows. Nothing persists (I6). |
| The parse worker dies holding a job (it exits, or an uncaught error kills it) | enforced | The job rejects with `ParseWorkerDiedError`: a per-run `BLOB_PARSE_WORKER_DIED` on the projection lane, `RESOURCE_PARSE_WORKER_DIED` on the registry lane, never `BLOB_PARSE_FAILED`, never stored (I6). Seeded with a worker that calls `process.exit(1)`: the file is refused, nothing is stored, and the next run re-attempts it. |
| A broken install reported as a worker death of each document in turn | enforced | A worker posts `ready` once its module graph has loaded. A thread that dies before it, or three threads in a row dying (or stopped at `timeMs` before its job's parser loaded, which the worker announces once per kind before that parser runs) with no answer between them, is a broken install: every held, queued and later job fails with a `ParserUnavailableError`, which every lane rethrows (the run fails loud, nothing is blamed on a document, nothing is stored). Seeded with a worker entry that throws as its module loads, one that loads and dies on every job, and one that loads and never answers (three `timeMs` stops, then parser-unavailable); an answer between deaths resets the count, and a time breach after the parser loaded is a slow document, never counted: three pathological documents stopped at once on three fresh threads stay three `timeMs` refusals (the width seed below). |
| A parse pool runs wider than its size while breached threads exit | enforced | A thread terminated at a time or heap limit, or one that died uncontrolled and is still exiting, counts against `size` until its `exit`; only then is its replacement spawned, and shutdown awaits it. Seeded by breaching every thread of a pool at once with jobs queued behind: the live threads, counted from each `Worker`'s construction to its `exit` (`diagnostics_channel` `worker_threads`), never exceed `size`; and with a thread whose `exit` lags the `error` it died of by 400 ms, a pool of one never runs two. |
| The parent cannot rebuild a worker's answer, or a stored entry's frontmatter | enforced | The frontmatter codec is loops on every encode and decode path (no spread, `apply`, `flatMap` or recursion), so no size or depth of input reaches a throw: a 2,000,000-element list round-trips. The worker emits only what the decode accepts: a frontmatter root is admitted only when it is a plain mapping (`isPlainMapping`, prototype `Object.prototype` or `null`, in `frontmatter-source.ts`), and a `!!set`, `!!omap`, `!!timestamp` or `!!binary` root is `frontmatterNotAMapping` like a sequence — seeded with each, cold and warm, no crash. The skill lane's own decode (`parseFrontmatter` in `agent-skills`) reads the same `isPlainMapping` and the same empty rule (a block that declares nothing is no frontmatter, never a non-mapping), so both lanes give one answer per block — seeded with the four typed roots, a sequence, a scalar and four empty shapes on both (`frontmatter-lane-agreement.test.ts`); `encodeFrontmatterValue` refuses any other root rather than writing one the decode would reject. A throw after a worker parse is VAT's defect (`ParseDecodeDefectError`), rethrown on both lanes, never a stored `BLOB_PARSE_FAILED` and never a finding; a stored entry whose encoding the codec refuses (`FRONTMATTER_VALUE_MALFORMED`, non-JSON included) is a cache miss, parsed again through the worker, while any other throw on a hit is loud like a bug anywhere in the cache. Seeded through a decode made to throw on each lane, and through a stored entry rewritten to a non-JSON encoding. |
| Cost: key-determined parse-limit breaches (output and input caps) re-attempted every run | accepted, counted | Bound: the caps are functions of the bytes, so the same file breaches the same cap every run and is parsed (or, for input, read) again each time; each breach is counted and named per run. Storing them under their limit is Deferred in the ADR. Rejected: storing them before the "failures stored under their limit" step lands (a second lane for one rule). |
| A process-wide heap flag (`--max-old-space-size` in `NODE_OPTIONS` or `execArgv`) lifts or lowers a worker's `resourceLimits`; a worker reaching V8's own ceiling kills the whole process | enforced; the parent-stall window accepted, bounded | The pool, never V8, enforces `heapMb`: it samples each worker's whole used heap every 50 ms (`exceedsHeapLimit`), which never understates the old generation. V8's ceiling sits at twice `heapMb` (`workerHeapCeilingMb`), because a worker that reaches it dies with a FATAL out-of-memory that took the process down in 3 runs of 4 at 64 MiB on Node 26. A child process run under a 4 GiB flag still stops at `heapMb`; under a flag that lowers V8's ceiling the job is stopped at half of it, re-read from every sample's `heap_size_limit`, and the refusal names that value. Seeded, each in a child process that must exit cleanly: a 64 MiB breach with no flag, three in a row, and a 1,024 MiB pool under a 64 MiB flag. **Assumption, accepted and bounded:** the sampler runs on the parent's event loop, so a parent blocked synchronously reads late. The stall-to-crash window, from the job crossing its applied limit to V8 reaching its ceiling at twice that, is about 3.4 s at the defaults and about 0.85 s under `--max-old-space-size=512` (applied 256 MiB). A breach in that window ends with V8 stopping the worker: either the process crashes loudly (FATAL out-of-memory, as at 64 MiB above) or, measured under a 512 MiB flag with the parent stalling 600, 1,500 and 3,000 ms at a time (3 of 3 runs), the worker's `ERR_WORKER_OUT_OF_MEMORY` reaches the pool as a `heapMb` refusal naming V8's ceiling, never the sampler's bound, which did not stop it (`ParseLimitError.heapCeiling`): twice the bound the last sample enforced when one landed, and when none did, a ceiling it says is unknown, since a process-wide flag overrides it. Either way, never a wrong answer. Seeded in a child process under a 512 MiB flag whose thread blocks 400 ms at a time, back to back, while a heap-breach document runs: refused cleanly at exactly the sampler's bound (`256 MiB heap, lowered from 1024 MiB …`); the same at 600 ms stalls: refused naming V8's ceiling, never 256 MiB, and the child exits 0; and in-process, a worker that answers samples for 300 ms and then dies with `ERR_WORKER_OUT_OF_MEMORY`: refused at `V8's own heap ceiling, 2048 MiB heap`, never the sampler's 1,024 (`parse-pool.test.ts`). Supervising the pool off the main thread is Deferred in the ADR. |
| The wall-clock limit includes a cold worker's first parser load | accepted | Bound: `timeMs` is set with headroom over the load plus the slowest measured parse ([limits](./fact-extractors-limits.md)); a breach is per run, so a slow start re-attempts next run. |
| A parse outside the two crawl lanes runs in-process, unbounded: `parseFileCached` in skill packaging, skill validators, post-build checks and the CLI; direct `parseMarkdown` in `referenced-path-missing.ts`; and the skill lane's own frontmatter decode, `parseFrontmatter` (skill validation, import, identity, compat, the inventory and the settings checker) | accepted until those callers move onto the pool | Bound: only the files a skill's link graph reaches, never the resources corpus. A stack overflow in `parseFileCached` falls back to ONE bounded parse through a one-thread pool, so the answer is the worker's — admitted, or refused under the worker's own limit and code — and a cold run and a run warmed by a crawl give the same verdict (I0): seeded in a child process with a 250 KiB main-thread stack, 3,000 nested blockquotes are admitted cold and warm and 20,000-level frontmatter is a `ParseLimitError` cold and warm (`parse-file-cached-fallback.integration.test.ts`). A stack overflow in `parseFrontmatter` or a direct `parseMarkdown` is caught and reported as the error finding `RESOURCE_PARSE_LIMIT_EXCEEDED` naming the file, in the sentence every lane uses (`inProcessRefusalIssue` / `inProcessRefusalEntry`; the CLI's name reads `skillDocumentOrOverflow` key the file by name and leave the finding to the validator), never a crash or a warning; seeded at 50,000 levels. A hang or a heap exhaustion there still blocks or kills the run (I8 holds for the crawl lanes, `addResource` and the overflow fallback only). |
| A parse under other limits files facts the default bounded route would refuse, so a later crawl admits the file from the shared cache | enforced | Every cache write, parent and worker alike, passes one guard in `ParseCache.setByKey`: an entry is filed only when the bounded route would admit the same bytes under the default limits (`storableUnderDefaultLimits`: input size and the output caps, by the one `outputBreach` the worker applies). So an in-process parse (`parseKeyed`), the overflow fallback's write (`parseFileCached`, a one-thread pool under the defaults), the wire transport's parent write, the cache-transport fallback and the worker's own write all file nothing past the defaults. Seeded: an in-process parse of a document over `outputRows`, and a pool under a looser `outputRows` on each transport, then a default bounded crawl over the same cache, which refuses it each time. A run under TIGHTER limits a caller names (API only) may store a success a default run would also admit, and I6 serves it to the tighter run: accepted, as no CLI surface names limits. |
| A check or query answers at exit 0 over a corpus missing a parse-limited file | enforced for `resources check` and every crawling verb; accepted, bounded, for `resources query` | `vat resources check` reads the population's refusal rows (`parseRefusedRealizations`) and files each refused file as a finding at it under its refusal code, before the checks' own findings, through the one finding resolver (`resolveFindings`) over the whole `resources.validation` — its `allow` list first, then its `severity` — as every other verb resolves it: an error by default, so the run fails closed. Held by `population-refusal-report.system.test.ts`: `resources check` exits 1 over a refused file, 0 with one `allow` entry naming it (as `validate`, `scan` and `rag index` do), and names it in the sentence every lane uses. A store hit cannot hide one: a refusal is never filed, so its key is held by nothing and the hit re-derives it. `vat resources query` has no verdict to fail; it answers over the rows it has, and the refusal is counted and named on stderr in the blob refusal summary (`populateAndReport`) — accepted. Every crawling consumer of the registry reports each file it enumerated and did not admit (unreadable, or its parse refused) through one contract, `not-admitted.ts` in `resources`: the same code and sentence, resolved through `resources.validation`, counted in `examined` whatever it resolves to, and scoped to a `--collection` by the collection's own patterns — `vat resources validate`, `vat resources scan`, `vat rag index`, skill packaging and its validators (a refused file the skill reaches, or a bundled asset, admitted in one `addResources` batch — one dispatcher, so a broken install trips the pool's breaker as `ParserUnavailableError` rather than refusing the first asset; seeded in `bundled-assets-broken-install.integration.test.ts`), and the inventory on both of its lanes (`extract-skill.ts`, a `parseRefused` row; the projection lane reads the same refusal from the population). Held from the tree by `parse-refusal-readers.test.ts` (dev-tools), a textual enforcer that judges each FILE — that it reads a refusal source, never that every crawl in it reaches one — in three arms, each table asserted both ways: a file that crawls (`crawl`, `addResources`, `fromCrawl`, a listed registry builder) reads `getParseRefusedResources()` or `getNotAdmitted()`; a file that calls `.addResource(` classifies `isPerRunParseRefusal(`; a file that runs a population (`populate(`, a listed population builder) reads `describeBlobRefusals(` or `parseRefusedRealizations(`, directly or through a listed reporter (`populateAndReport`). Each may instead be a listed builder whose callers are held in turn, or be listed with where its refusals are reported. |
| `vat rag index` indexes text that changed after the crawl under the facts of the bytes admitted | enforced (I2a) | The indexer re-hashes the text it reads with the registry's own `calculateChecksumFromContent` and compares it with `resource.checksum`; a mismatch is that resource's error (`RAG_DOCUMENT_INDEX_FAILED`) and nothing is written for it. Seeded by changing a file between admission and indexing. |
| Cost: a small cold corpus parses through one worker instead of the main thread | accepted, counted (the `wire-roundtrip` tier row, `TierPass.WireRoundtrip`, of the lab's `parse` facet) | Measured on 20 documents under load: the main thread waits 835.6 ms for the worker round trips, where the in-process parse took 458.5 ms; wall time about −1% to +64% min across A/Bs whose pairs disagreed, worst `resources query` cold-small at +464.9 ms ([limits](./fact-extractors-limits.md)). Accepted because a warm run starts no worker and the cost is fixed per run, not per file. Rejected: keeping an unbounded in-process route for small runs (I8). |
